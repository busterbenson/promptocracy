# AGENTS.md — working on Promptocracy

Read this before changing anything here. It holds the decisions and conventions that aren't obvious from the code. `CLAUDE.md` imports it.

## What this is

Promptocracy is a self-amending game (after Peter Suber's Nomic) at promptocracy.us. This repo is the **platform**: one Cloudflare Worker + D1 database hosting many games. Each game has its own public GitHub repo holding its rules (first one: `busterbenson/promptocracy-rickshaw`, Rickshaw Game 1). Chalant, the AI, is the game's **moderator** (never "referee").

Owner: Buster Benson. He decides game design; agents build what he approved.

## Hard rules for anyone working here

1. **Don't invent mechanics.** The game grows through play. If a build needs a mechanic that isn't decided, stop and ask (with a lean). Don't add claiming, terrain, harvesting, tile properties, etc. by default.
2. **The rules are the game.** Every rule change ships as rule text + enforcing code + tests, together. Never add rule text before the PR that implements it; never add behaviour no rule states. Rules that need judgment call a small model (Haiku/Jev/Flash) behind a test with recorded answers.
3. **Every engine function is claimed by a rule.** Tag it `@rule <n>` (JSDoc). `scripts/check-rule-claims.mjs` (in `npm test`) fails on unclaimed engine code or a tag naming a rule that doesn't exist. Site plumbing (sign-in, email, DB) is claimed by 302 / 102. Repealing a rule means its code is removed or reassigned in the same change.
4. **No helper text, anywhere.** No intro paragraphs, captions, eyebrow labels, hint lines, "how this works" asides, reward reminders ("+10 if it passes"), restated rules ("One proposal a day") or "log in to…" nudges. What the UI shows is labels, data, state, and a reason next to a disabled control. If it matters to play, it's a rule: point at it with a rule pill. (Buster, 2026-11-20: "Just have a general rule against random helper text.") Mockup copy that breaks this rule is not built, even when a checklist line asks for it.
5. **Vocabulary:** moderator (not referee); players "join the game" (not "take a seat"); creatures (hostile / neutral), Blob, Ghost, Crow; "Use this piece" / "Change your piece"; "You" for the center-on-my-piece button.

## Architecture (decided 2026-11-19; detail in docs/step1-plan.md)

- **The game's repo is the game.** Per rule: text in `RULES.md`, code in `rules/<n>.ts` (handlers for engine hooks), tests in `rules/<n>.test.ts`. Settings (`[setting: key]`) are data in `settings.json`, no code.
- **Bundled at deploy.** A Worker can't load code at runtime, so the build fetches each game repo at its latest `day-N` tag, validates it (manifest, allowed paths, lint: no network calls, no imports beyond the engine API), runs its tests, and bundles text + settings + modules. The rulebook served is the bundled text, so it always matches the running code.
- **Shared, dumb engine.** It runs the day loop and calls hooks. Rules never edit each other's code; each registers handlers. Combine modes: `veto` for can-I hooks (any rule may refuse, with a reason naming its rule), `sequence` for effects (rule-number order), `decide` for single values (precedence rule picks; lower number wins). A capability the engine lacks gets a new hook for all games, separately from the rule that needs it. A function claimed by more than 3 rules is a smell: split it into hooks.
- **The moderator** may only touch a game repo's `RULES.md`, `settings.json`, `catalog.json`, `rules/`, `rulings/`. It runs on Buster's Mac mini (headless Claude Code via launchd), not in the Worker.

## The day (decided 2026-11-19)

- Days run midnight to midnight in the game's time zone. **No early close.**
- **Midnight lock:** from midnight until the previous day is processed, the game is locked on web, API and MCP (no moves, votes, proposals, End turn). Every write route checks the clock itself, not only the cron's flag. The page says the moderator is processing day N.
- A turn: move one space (or change your piece's shape instead), propose up to 3 changes (setting `proposals.per_day`, rule 103.2), vote on each proposal. **End turn is final**; votes can change and a proposal can be withdrawn until midnight or until you End turn.
- Votes are hidden until midnight. **Not voting counts as no** for every mark, except on the Champion's change (402.4). The electorate is fixed at the start of the day.
- Proposals: reword a rule or one clause (scope step: whole rule vs clause), add a clause, add a rule (pick a block), repeal, move, lock/unlock (unanimity mark); catalog proposals come with step 3. Code drafts mechanical changes; a small model (Haiku) drafts rewording. The vote mark is stored at confirm.
- **Midnight processing:** count votes (code), roll proposals, apply each passed proposal in order as one commit (text + code + tests) in the game repo, tests must pass, tag `day-N`, deploy, unlock when the deployed version matches. Points (401) when a change takes effect.
- **Failures:** each rule implementation has its own budget (time + effort, a setting). Over budget, or not done by **2 am**, = "not applied", no points, and the proposal goes **back to its owner with the moderator's reason and a suggestion** (split it, simplify it). Two rules that can't both hold: the core (unanimous) one prevails over a majority one, otherwise the **older** one prevails; the other goes back with reasons (a core meta rule).

## Rule text decisions

- 600 (hearts + creatures) and 700 (making things) are **starter rules**, but their text enters a game's RULES.md in the step that ships their code (step 2, step 3).
- Death, Ghosts and the ending (Buster, 2026-11-22; replaces the old 601.4 Ghost / 601.5 moon bullets, no moons): 3 hearts (601), hostile creatures appear on nights nothing was applied, chase and bite (602), 0 hearts = dead: no vote, no turn, the piece lies where it fell (603.1); a living player next to it can give a heart to revive them before the Ghost rises (603.4: giver keeps 1, once a day, free of the move); after 3 days (`death.ghost_days`) they rise as a **Ghost** (603.3, 604): the same turn checklist, Move and End turn kept, Vote and Propose off, its piece replaces the player's and can't be changed, its moves chart tiles. The game ends by rule 404 (below). Rule text is in Rickshaw's RULES.md and `templates/RULES.md`; the engine side is the `night` and `ending` hooks (`src/engine/board-night.js`, `host.ts` nightBoardStatements), migration 0019.
- The 29 approved additions/rewordings are in `docs/rules-parity.md` (give-a-heart limits, 501.4 adjacency = 8 neighbours, End turn vs 104.3, …). Their numbers follow the approved **reorganization** in `docs/rules-reorg.md`: block 100 = rules about rules + everything the shared site does (103 Proposals, 107 The night, 108 When rules conflict, 109 Numbers and settings; 110 was retired 2026-11-20, see below); blocks 200+ = what each game's own rule code does; 302 retired. Use the reorg numbers in rule text and `@rule` tags.
- **Three levels, no text under a title (Buster, 2026-11-21; rule 109.1).** A block holds rules, a rule is its title and its numbered clauses, a clause holds the text. A rule has no text of its own: the ten that did (101, 201, 204, 301, 401, 403, 501, 502, 503, 505) state it as clause N.1, and a new rule's text is its N.1 (the drafter numbers it). Citing a rule cites all its clauses. A rule's clauses run N.1..N.n **with no gaps before day 1**; once play starts a repealed clause leaves its number empty and nothing renumbers. `checkRulebook` (`src/engine/rulesmd.js`, run by the bundler and every game's rulebook test) fails text under a title and a citation of a block, rule or clause that doesn't exist, always; the no-gap check runs only with `beforeDayOne` (the bundler passes it for a game whose latest tag is day-0.K; the platform test passes it for the template). 109.2 is the settings clause. "Say each thing once" is **guidance, not a rule** (`docs/rules-voice.md` 8, Starling's and the drafter's prompts, `moderator/APPLY.md`, `moderator/RULING.md`): nothing rejects a restatement.
- **Marks are on rules, never on blocks (Buster, 2026-11-21; rules 105.1, 105.2).** Every rule heading ends in `[u]` (unanimous) or `[m]` (majority) and a block heading has none; `checkRulebook` fails a rule without a mark and a block with one. Majority is what anything unspecified is. A proposal that adds a rule makes it majority unless the proposal marks it unanimous (the draft's `mark`, kept on the draft row until confirm; Starling's `add` takes `mark: "unanimous"`), and then it needs every player; a move keeps the rule's own mark; "mark" proposals are on a rule, not a block. The Era's winning score is the setting `eras.points_to_win` (rule 402.2), read by `rules/402.ts`.
- **Renumbering is free until the first game officially starts** (Buster, 2026-11-19): moving and renumbering rules for better organization needs no proposal before Rickshaw Game 1 starts. After that, renumbering is a "move" proposal like any other.

## Game design decisions (Buster, 2026-11-20)

- **No untouchable rules.** Rule 110 ("What no proposal can change") retires. Its 8 items (sign-in, midnight-to-midnight days, the daily proposal limit, End turn, hidden votes, votes counted by code, the lock, the deadline) become ordinary rules with a **unanimous** mark, each in its own block. Each moves behind an engine hook a game rule controls, the way 107 controls the night's order. Until an item's hook ships, a proposal on it is refused at drafting with the reason "not wired yet"; it never passes and does nothing.
  - **Status (2026-11-20): rule 110 is gone from the template and from Rickshaw.** All 8 items are still platform-run, so none has its hook yet: each is on `NOT_WIRED` in `src/lib/proposals.js` (102.4 sign-in, 103.2, 104.4, 104.5, 107.1, 107.6, 202.4, 203.1) and rule 103.6 (which states the restriction and lists the parts, itself included; 103.5, 103.7 and 103.8 are the action rules) says a proposal that changes one is refused at drafting, "Not wired yet: rule N", with no P-number. A reword that keeps the text and only sets a setting (`proposals.per_day`, `game.timezone`) still drafts: settings are data the site reads. A part leaves the list, and 103.6, in the PR that ships its hook: that PR edits `NOT_WIRED`, `templates/RULES.md` and the game's `RULES.md` together (once a game is live the game-side edit is a direct commit by the moderator's operator, since a proposal cannot change a not-wired part); the platform test pins the template's 103.6 to `NOT_WIRED` and each game's rulebook test pins its own. A draft that would conflict with a not-wired part (a repeal or move that leaves it citing nothing, or a conflict the model names) is refused too. Marks are per rule: 202 and 203 carry `[u]` as a whole (their other clauses, move distance and the time-zone setting, now need everyone), and so does every rule of the old block 100.
- **Eras** (built: rule 402, migration 0011). Winning an Era makes you Champion. The Champion names the next Era and can change one rule without a vote, a unanimous-mark rule included. The change passes **unless every other living player votes against it; not voting does not count as against** (the one place that differs from "not voting counts as no").
- **How the game ends (rule 404, Buster 2026-11-22).** No survival win. Three endings: **Paradox** (the only one with a winner; a moderator ruling names a living player, 403.1, 404.2), **Last one standing** (a night's deaths leave one living player: nobody wins, they are the King of Ghosts, 404.3) and **Everyone dead** (404.4; the last two dying the same night count as this, checked once at the end of the night after every bite). Ghosts and creatures are not alive. Ending sets `games.status = 'over'` plus `ending`, `ended_day`, `ending_player_id` (src/lib/end.ts); the existing gates then stop everything and `finalizeDay` opens no next day.
- **Action proposals: yes**, as a fixed catalog of coded action types (resurrect, grant, move...). The vote needed is the stricter of the action's own mark and the strictest rule it touches; no override; recorded in History. Core rule 103.5: an action can only do what the game's rules already allow. Adding an action type is a rule change.

## Design reference

- The agreed UI is the clickable mockup "Promptocracy Play Mockup" (claude.ai artifact 9fUrG28r7RVxJi9Lu7Q9wo, v32). `docs/spec-checklist.md` is the acceptance checklist derived from it (159 items by step and screen, plus OPEN questions and sample-data items NOT to build). Each PR ticks its items in the PR body and names anything it leaves out.
- Button emphasis: filled = expires or already started; ghost = available, not urgent; link = always available and reversible. One filled button per surface. The move bar shows at most one contextual action.
- Links: rules/clauses are accent pills with the number only (tap = preview, then open, with Back); proposals are ink pills ("P8"); players are pills with their piece + name.

## Operations

- **Deploy:** merging to main deploys the Worker via Workers Builds. Verify on the live site after.
- **D1 migrations:** back up first, apply to preview, then prod, with the d1-migration skill (`~/chalantbot/repos/skills/d1-migration/`). Never `wrangler d1 export --remote` on a live DB.
- **Art (R2 + Workers AI):** drawings live in the private R2 bucket `promptocracy-art` (`promptocracy-art-preview` for previews), keyed by the SHA-256 of the bytes: `tmp/<sha>` as made (a bucket lifecycle rule, `tmp-30d`, deletes them after 30 days) and `art/<sha>` once saved to an entry. Only the Worker serves them, at `/<slug>/art/<sha>`. The model is the `[ai]` binding (`IMAGE_MODEL`, default `@cf/black-forest-labs/flux-2-klein-4b`; `@cf/black-forest-labs/flux-1-schnell` is the fallback). `wrangler dev` cannot start with an `[ai]` binding without a Cloudflare login, so the tests run on `wrangler.test.toml` (generated, gitignored: the same config without `[ai]`) and draw through the `ART_STUB` stand-in (`src/lib/art.js`). The daily sweep is the second cron (03:15 UTC). **A drawing's prompt is the house style plus ONE per-kind block** (`KIND_BLOCKS` in `src/lib/art.js`, picked by the entry's catalog kind): the creature block is the character direction, the structure, item, feature and tile blocks say what an inanimate thing or a ground tile is and carry no face, eye or limb words (naming one invites it; the model has no negative prompt). Add no example subject and no patch for one bad drawing to any block. After each drawing a cheap vision model (`claude-haiku-5-5`, `src/lib/art-check.ts`) answers that kind's question; only a clear yes passes, a fail is redrawn once if the Worker has the time (it usually does not: a drawing takes 10-16 s of the 30 s a Worker keeps working after its response), and the outcome is written on the draw (`art_draws.reason`: `check failed: ...` or `unchecked: ...`; empty = passed).
- **Secrets:** never print them. Cloudflare token comes from `~/chalantbot/.env` (`CLOUDFLARE_WORKERS_TOKEN`).
- **Game repos:** a game in setup (Rickshaw has one player) can have its starter rules edited directly; once play starts, rules change only by proposal.
